# Scenario placement and palette records (`mod_1e380_f1`)

This part of `mod_1e380` interprets scenario placement records, finds and duplicates custom starting units, and initializes palette cycles.

| Address | Function | Disassembly evidence |
| --- | --- | --- |
| `0x1e3b4` | `ApplyScenarioTerrainOwnerRects` | `0x1e3be–0x1e3de`: tests for `0xff`, remaps byte `+4`, calls `TerrainFillRectOwnerMask`, and advances five bytes. The sentinel branch targets the shared tail at `0x1e3ac`; the reference returns sentinel + 2. |
| `0x1e3e0` | `FindCustomStartAnchor` | `0x1e3e8–0x1e426`: selects the player's or enemy's race and adds 2 for group 2, otherwise `0x28`. `0x1e430–0x1e462` returns the first matching slot, or the pointer just past 200 slots on a miss. |
| `0x1e464` | `PlaceCustomUnitCopies` | `0x1e474–0x1e522`: owner zero and nonzero count gate the scenario-mask update; unsupported types on that path call `FatalError("place_custom")`. `0x1e527–0x1e57b` starts the copy loop at 1 and passes coordinates, type, owner, and a size-table pointer to `fn_2e650`. |
| `0x1e644` | `LoadScenarioUnitRecords` | `0x1e650–0x1e6ce`: scales coordinates by eight, remaps the owner, conditionally swaps the type, and calls `UnitCreate`. `0x1e6d3–0x1e718`: consumes the optional amount, rounds type `0x32` amounts, and skips two bytes at the sentinel. |
| `0x1e724` | `LoadScenarioPaletteCycles` | `0x1e72f–0x1e766`: clears existing cycles and sends each three-byte record to `PaletteCycleSetup`. `0x1e76b–0x1e78a`: enables IDs selected by the mask and returns immediately after the zero period byte. |

## Layouts and calling conventions

- **Terrain owner rectangles:** five bytes per record, with the remap index at `+4`; `0xff` in the first byte terminates the list (`0x1e3ba–0x1e3de`).
- **Anchor scan:** `unit_array` (`0x59640`) points to `0x5c`-byte slots. The scan rejects flags `& 0x0207` at `+0x10` and compares owner byte `+0x1e` and type byte `+0x1b` (`0x1e429–0x1e45c`). The race words are at `0x50088` and `0x5008a`; the group word is at `0x50e52`.
- **Copies:** signed coordinates come from anchor offsets `+0x0a` and `+0x0c` (`0x1e527–0x1e537`). The size table at `0x51abc` has four-byte entries (`0x1e544–0x1e552`). The pointer is the fifth Watcom register-convention argument, passed on the stack (`0x1e556–0x1e573`). The scenario mask at `0x50004` is a dword.
- **Unit records:** four bytes `[x, y, type, owner_index]`, optionally followed by `[0xfe, amount]`. The suffix is consumed even if creation fails. On success it writes `amount << 8` to unit dword `+0x54`; type `0x32` rounds that dword down to a multiple of 100 using unsigned division (`0x1e6d5–0x1e713`). The custom-game word at `0x50e4e` gates the swap table at `0x51122`: mapped owner 0 or 1 uses the table only when its corresponding race word equals 1 (`0x1e683–0x1e6b1`).
- **Palette records:** `[period, first, last]`, with zero period terminating the stream. Setup gets `(id, period, first, last, NULL, 0)`; setup and enable take stack arguments and the caller cleans up (`0x1e74c–0x1e780`). IDs start at zero; the enable mask at `0x500de` is read as a word (`0x1e734–0x1e73b`, `0x1e76e–0x1e776`).

## Test coverage

`tests/test_mod_1e380_f1.py` guards the T3 matches for the terrain-kind, placement-stream, and custom-start orchestration sources. A separate near-miss guard requires all five reference sources to remain non-matching at T3. T4 compares return pointers, the scenario mask, unit amount writes, and relevant call arguments or ordering against the original with callees stubbed. The fatal path is not exercised. These tests require the original executable and `$WATCOM`; no execution result is claimed here.
