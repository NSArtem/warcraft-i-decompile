# Game session lifecycle (`mod_19470`)

This module selects a scenario, initializes or restores the session, drives its frame loop, handles pending loads, and releases in-game resources.

| Address | Function | Confidence | Disassembly evidence |
|---|---|---|---|
| `0x19470` | `GameSetRandomSeed` | high | `0x19470` stores EAX at `0x50d7c`; the restore path calls it at `0x19607`, and `NetLinkHandshake` (`0x23edc`) is another caller. |
| `0x194a8` | `GameResolveCustomScenario` | high | `0x194ab–0x194c7` conditionally copies the selected map words. Group 3 enters the index switch at `0x194d5–0x194ef`, then rolls the map index at `0x1954b–0x19561`. `0x19568–0x195a0` computes `group * 7 + index` and adds `0x95` for network play or `0xaa` otherwise, keeping the low word. |
| `0x195ac` | `GameInitSession` | high | `0x195bf` splits on the save pointer. `0x195cf–0x195f1` read three save blocks; `0x1966b–0x1968b` open and read the scenario resource, with the `game:1` size error for lengths above `0xbb8`. `0x19705–0x19758` initialize the map and units, release the save image when indicated, and center fresh custom sessions. |
| `0x197b0` | `GameUpdateFrame` | high | `0x197b8` gates event pumping on movie state; `0x197c7–0x197d6` test the two short arguments, with packet work nested under simulation work. `0x197fe–0x19808` invalidate layer `0x16`, update the screen, and update palette cycles. |
| `0x19810` | `GameRunActiveLoop` | high | `0x1981e–0x19829` test the signed high word of the mode dword for 3. `0x19836–0x19893` compare clock and deadline as unsigned values, rebasing on a speed change or critical error. `0x198a3–0x198e9` decrement and reload the packet countdown on due simulation ticks. |

## Data layout

- The restore calls at `0x195cf`, `0x195e0`, and `0x195f1` thread the stream pointer through `0x14` bytes at `prefs_block` (`0x532b4`), `0xbb8` bytes at the scenario image base (`0x50004`), and `0x200` bytes at the saved-state base (`0x50d7c`). The last block starts with the dword RNG seed, followed by the minimap redraw and scenario-number words (`0x50d80` and `0x50d82`). The race words at `0x50088` and `0x5008a` are preserved across a custom resource load (`0x1964b–0x196a5`).
- Custom map index and group are adjacent words at `0x50e50` and `0x50e52`; `0x194b5–0x194c7` source them from the low words of map-choice entries 0 and 5. Initialization masks the dword at `0x51214` with `0xa4000000` and writes the first two visibility words at `0x51de6` (`0x196cb–0x196f1`).
- The loop uses a dword speed cache at `0x594f0` and words for delay phase and packet countdown at `0x594f4` and `0x594f6`. The delay table at `0x517f1` uses two byte entries per speed (`0x1987d`); the packet interval table at `0x517ce` uses five byte entries per speed (`0x198d5–0x198e9`). `game_mode` at `0x59616` is the high word of the dword read from `0x59614`.
- Pending-load state includes the slot file pointer at `0x59610`, the request word at `0x516b0`, and the pending image pointer at `0x599b0` (`0x19918–0x19974`). The layer array at `0x5aa90` has 32 records in the header; `0x19b23–0x19b28` establish the `0x12`-byte stride and the first-word store, not the meaning of the remaining bytes.

## T3 and T4

The T3 test guards `game_run_session.c`; the near-miss guard expects all seven reference files to remain non-matches. The reported blockers include unresolved data/call or switch-table relocations and register or prologue differences. The T4 tests compare each reference with the original under controlled inputs, observing watched memory, integer return values where applicable, and ordered callee logs. The loop test sets incoming ECX for the warm-cache case and bounds active execution through the mission-end stub. The initialization test covers successful-size resource reads and stream restore, not the fatal oversized-resource path. Stubbed callees' own implementations are outside this coverage. These checks have not been run here.
