# mod_209e0 (0x209e0..0x20a7c): network packet checksum / send / receive

Packet layout: +0 u16 checksum, +2 u16 word (seq/id), +4 u8 length, +5 u8 error flag; checksummed payload starts at +4.

| Addr | Name | Notes |
|---|---|---|
| 0x209e0 | NetChecksum(buf, len) | T3 matched (net_checksum.c). Header note: len may need to be u16. |
| 0x20a14 | NetReceivePacketChecked(pkt) | Calls the driver receive routine. Returns 0 if it returns 0. On -1 or a checksum mismatch it sets pkt[5]=1 and returns -1. Otherwise it returns 1. Reference only: the compiled code has an extra cwde (+0xb). |
| 0x20a50 | NetSendPacketChecksummed(pkt, word) | T3 matched (net_send_packet_checksummed.c). |

## Tests
- T3: `net_checksum.c` and `net_send_packet_checksummed.c` must still match.
- Near-miss guard: `net_receive_packet_checked_reference.c` must still fail to match.
- T4: `test_net_receive_packet_checked` runs the reference against the original at 0x20a14. The driver callee and NetChecksum (0x209e0) are stubbed. The driver stub's address is looked up from the symbol DB as `NetDriverReceiveChecked_`. Cases cover driver returns of 0, -1 and positive values, and checksum match and mismatch. The packet buffer is allocated in `init_emu`.
