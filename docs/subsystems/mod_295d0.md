# mod_295d0: the computer opponent's unit AI (0x295d0..0x2b1b0)

The object `mod_295d0` in `analysis/modules.toml` (0x295d0..0x2b1b0, 29
functions, "OPT" code `-s -ot -ol -4r -zp2`) is the **single-player computer
opponent**: the per-player AI state and tick, the AI's worker (work-site and
gold-mine) management, its building/rebuild choice, and the automatic
target/retreat/spell behaviour of the AI's units.

Names, prototypes, evidence: `analysis/symbols/mod_295d0.toml`. C:
`src/mod_295d0/` (one function per file, per the "one function per object"
rule). Declarations: `src/include/mod_295d0.h`. Tests:
`tests/test_mod_295d0.py`.

## 1. What the module is, and the evidence

The objects around it are the unit/order layer (0x104b0 unit combat,
0x13f60 order dispatch, 0x2ced0 the unit array). This object is called *from*
that layer, always for the player whose **player type** (`0x5008c[owner]`) is
**1**:

| caller | address | why |
|---|---|---|
| `UnitCreate` 0x2e6f4 | 0x2e950 → `AiInitUnitOrder` 0x29cf8 | a new AI unit gets its first behavioural state |
| `UnitRemove` 0x2e14c | 0x2e15a → `AiRemoveUnit` 0x29ea8 | drop a removed AI unit from the counters/site |
| `UnitIdleTick` 0x10ee8 | 0x10f32 → `AiWorkerTick` 0x2b064, 0x10fc7 → `AiSpellcasterTick` 0x2a8f4, 0x10fda → `AiIdleUnitTick` 0x2ab54 | the stop order's per-tick body, only when `0x5008c[owner] == 1` |
| `UnitRetaliate` 0x10d34 | 0x10e3c → `AiWorkerTick` | workers of the AI |
| `OrderUpdateStop` 0x14030 | 0x14041 → `AiWorkSiteStep` 0x298a0 | the harvest swing step |
| order 0x0d handler 0x1d1e0 | 0x1d25e → `AiWorkerTick` | after a build/harvest order |
| scenario start 0x195ac | 0x196fe → `AiReset` 0x295d0 | clear the AI state for a new game |
| per-tick routine 0x197b0 | 0x197d6 → `AiTick` 0x29a08 | the AI's own timer tick |

Internally the module is one closed system: `AiWorkerTick` drives
`AiChooseBuilding`/`AiBuildOrRepair`, `AiMineGold`, `AiScoutStep`,
`AiGuardStartArea`; `AiSpellcasterTick` drives the five cast helpers and the
same idle tail; `AiTick` drives `AiChooseAttackPoint` and `AiResetWorkSites`;
`AiWorkSiteStep`/`AiWorkSiteRelease` drive `AiWorkSiteAdvance`.

**The player type.** `0x5008c[player]` is read as `== 1` before every AI
action, and the spellcaster AI reads **column 1** of the per-player spell
table `0x50017` (rows 0..5 = global rows 3..8). Column 1 is player 1, the
computer side in a single game; the human player is column 0 (that is what the
status panel tests, `0x27ef6..0x28060`). The `UnitRetaliate`/`UnitIdleTick`
reference C in the mod_104b0 area calls the same value `human` - that name is
misleading (it is the *computer* player; the remote human is type 2, see
UnitRetaliate 0x10d7c), see the change requests.

**Unit types** (from the `unit_names` table 0x54e54): 0/1 Footman/Grunt,
2/3 Peasant/Peon, 4/5 Catapult, 6/7 Knight/Raider, 8/9 Archer/Spearman,
0x0a/0x0b Conjurer/Warlock, 0x0c/0x0d Cleric/Necrolyte, 0x0e..0x12 the named
heroes, 0x13..0x1f monsters/summons, 0x20/0x21 Farm, 0x22/0x23 Barracks,
0x24/0x25 Church/Temple, 0x26/0x27 Tower, 0x28/0x29 Town Hall, 0x2a/0x2b Mill,
0x2c/0x2d Stables/Kennel, 0x2e/0x2f Blacksmith, 0x30/0x31 Stormwind/Black
Rock, 0x32 Gold Mine, 0x33 corpse.

## 4. What the AI does

* **Tick** (`AiTick` 0x29a08): every 0x320 ticks re-pick the attack point;
  the wave timer (0x1770, or 0x15e/0x1770 by the mission bits 0x84/0x40, or
  switched off) releases all workers from their sites (`AiResetWorkSites`).
* **Attack point** (`AiChooseAttackPoint` 0x29644): a 4x4 grid over the map,
  counting **player 0's** units (a building counts 4, a unit 1); the fullest
  cell's centre (`cell*16+8`) becomes `ai_attack_point`.
* **A new unit** (`AiInitUnitOrder` 0x29cf8): a town hall records the home
  point and, for player 0, seeds the attack point; buildings clear flag 0x400;
  catapults do nothing in the two escape scenarios (0x8d/0x8e); summoned
  creatures (0x13..0x1f) attack in a linked game and "return" otherwise; other
  units get an attack flag when mission bit 0 is set, else try to wake a
  dormant scenario unit (`AiWakeUnit`) and finally pick a work site.
* **Workers** (`AiWorkerTick` 0x2b064): unload at the town hall when carrying;
  otherwise build/repair (while fewer than 2/3 of the workers are busy), mine
  gold (`AiMineGold`: the mine minimizing dist(home,mine) +
  dist(player-0 home,mine)/4 + dist(mine,unit)), sweep the map
  (`AiScoutStep`), else stay near the start area.
* **Combat units** (`AiIdleUnitTick` 0x2ab54): attack the best nearby target
  (priority table 0x51d28, buildings disfavoured), defend a *damaged* town
  hall, march on the attack point when flag 4 is set, else return to the work
  point / guard the start area.
* **Spellcasters** (`AiSpellcasterTick` 0x2a8f4), by type and research row:
  Cleric 0x0c: row 5 → invisibility on a moving Knight/Archer, row 3 → healing
  on the most damaged friend (21x21 box); Conjurer 0x0a: row 2 → queue summon
  water elemental, row 0 → queue summon "scorpions", row 1 → rain of fire
  (0x1a) at the attack point; Necrolyte 0x0d: row 5 → unholy armor on a
  fighting wounded friend, row 3 → raise dead on a nearby corpse; Warlock
  0x0b: row 2/0 → queue daemon/spiders, row 1 → cloud of poison (0x1b).
* **Work sites** (`AiWorkSiteAdvance`/`AiWorkSiteStep`/`AiWorkSiteRelease`):
  the map's site table is a list of weighted entries; a worker counts in at a
  site, and when the site's worker count reaches `ai_site_limit` the unit is
  moved on to the next record; when the wave timer fires every unit is
  released.

## 7. Open questions

* **The building priority tables.** The code reads them as
  `[type + 0x55100]` and `[type + 0x55113]` with type 0x20..0x32, i.e. the
  entries really used are at 0x55120..0x55132 and 0x55133..0x55145, 0x20 bytes
  after the symbols the original's relocations name. The bytes at
  0x55100..0x5511f are the tail of the research-description pointer table
  0x550f8, so the original build's symbols sit ahead of the table contents;
  the values are priorities (farm 50/45, barracks 40/35, town hall 120/45,
  mill/blacksmith 20/15, Stormwind/Black Rock 0/50, mine 0/0). Honest
  confidence: low on the intent, high on the bytes.
* **`AiChooseBuilding`'s two branches.** Bit 0x200 of the flags word is set by
  fn_2e96c for an AI unit that is taken off the map (flags = 0x200, and a
  building gets +0x4a = 0xff); the "down" table is used for those buildings
  and the "up" table for standing ones at >= 3/4 hp. The names `down`/`up`
  describe that split, not a game rule.
* **`ai_site_count` / `ai_helper_count`** are never incremented in the image
  outside this module (UnitRemove sets `0xffff` as a "recount" marker), so
  their exact meaning (units working, units awake) is inferred from the
  reads.
* **`AiWakeUnit`'s random gate** is inverted between its two entry paths
  (scan on `rng & 3 != 0` when the helper counter is set, on `== 0` when it is
  clear). Reproduced as the code does it.
* **The area spell ids** (Conjurer 0x1a "rain of fire", Warlock 0x1b "cloud of
  poison", and the Conjurer's 0x19 summon) follow the order ids the dispatch
  table 0x5158c documents; whether the game's race/spell pairing matches the
  unit names is not resolved here.
