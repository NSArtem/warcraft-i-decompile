## Behavior and coverage

Types 1, 2, and 4–7 return 0 and advance the expected word on an exact match (`0x12e89–0x12ea9`); receiving the immediate successor sends a request for the missing sequence and returns 2 (`0x12eaa–0x12eec`). Type 8 returns 0 for either sequence without advancing (`0x12ef6–0x12f23`). Both successor comparisons are widened, so zero is not the successor of `0xffff`; only the stored word increment wraps. Type 3 scans from the requested sequence to the exclusive resend limit, sends found records, and returns 1 (`0x12e43–0x12e88`). Unsupported types and rejected sequences also return 1.

No T3 files are listed for this dossier. The T4 reference `net_process_received_packet_reference.c` has a reported entry codegen mismatch (the original starts with `push ebx` at `0x12dec`). The near-miss guard checks the codegen status separately from the differential test, which compares EAX, packet and global memory, and ordered lookup/send calls. The test stubs the callees; it does not test the ring lookup or checksum implementation. Runtime verification is pending execution with the original executable and Watcom.
