## Data and wrapping behavior

- `wrapped_text_lines` (`0x596a0`) is an array of 100 four-byte pointers into the mutable input buffer. `0x1c055`–`0x1c05e` appends an entry and advances the count. `0x1c0b5`–`0x1c0bf` writes a null sentinel only when the count is below 100. That check gates the sentinel, not the append.
- `wrap_text_buffer` (`0x59850`) holds the input pointer, loaded at `0x1c030`. The loop skips leading ASCII spaces (`0x1c041`–`0x1c051`) and scans for spaces or NUL (`0x1c061`–`0x1c076`). The scan starts one byte past the current candidate, so the all-spaces test supplies zero padding beyond the terminator.
- `cur_font` (`0x5acf0`) is loaded into EAX at `0x1c081`; the candidate string goes in EDX. The routine temporarily replaces the candidate delimiter with NUL before calling `TextWidth` (`0x32060`). `cwde` and the signed comparison at `0x1c08d`–`0x1c090` accept an exact fit. On overflow the routine restores the delimiter, NULs the previous candidate boundary, and resumes one byte past it (`0x1c092`–`0x1c09e`). For an overwide first word that boundary is the line start.

## Regression checks

`tests/test_mod_1c020.py` checks the two T3 files for exact matches and guards the wrap reference against an unnoticed promotion. Its reported codegen difference starts at `0x1c02b` (original `xor edx, edx`, reference `xor eax, eax`). The wrap differential test compares the entire pointer table, the mutable buffer, and the ordered `TextWidth` call log using a deterministic length-based stub; it does not test real font metrics. These checks were not run in this response.
