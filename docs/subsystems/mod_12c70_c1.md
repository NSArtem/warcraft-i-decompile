# mod_12c70_c1 — network send

| Addr | Name | Notes |
|---|---|---|
| 0x131d8 | NetSendMessage | Stamps a sequence number into msg+2 from net_send_state[0], gets a ring slot via NetNextSendSlot(&net_send_slot), sets flag bits 0x40 (and 0xc0 if own_campaign) in msg[1] when dat_516ae is nonzero, copies msg[0] bytes into net_send_ring[slot] (0x88-byte entries) at +4, then calls fn_20a50(entry, len+4). |

## Data
- net_send_state[3] (u16): [0] is the sequence counter.
- net_send_slot (u16): current ring index.
- net_send_ring[10]: 0x88-byte entries. Bytes 0..3 are the header, and the payload starts at +4.

## T3/T4 notes
- The reference file `net_send_message_reference.c` is not a match. The original at 0x13216 does `xor ebx,ebx`, and the compiled output does `movzx eax, word ptr [0x58d9a]` about 0x3e bytes further on. The cause is codegen: the slot index is held and used differently.
- The T4 difftest compares the registers, the watched state and the logged callee calls. The only stub is fn_20a50, and its log records eax and edx. No stack pointers are logged.
- The message buffer is allocated inside `init_emu`.
- The test's addresses and its calls to NetNextSendSlot and memcpy are unverified. NetNextSendSlot and memcpy are not stubbed, and the test file contains no stub for them.
