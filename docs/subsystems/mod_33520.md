# Critical-error dialog setup (`mod_33520`)

| Address | Function | Evidence | Confidence |
|---|---|---|---|
| `0x337d0` | `CritErrInitDialog(void)` | Called by `fn_1da34` (`0x1da34`). Calls `CritErrInstall` at `0x337de`, clears the install flag at `0x337e3`, then draws two 58×15 button surfaces and a 286×48 panel (`0x33804`, `0x33821`, `0x3383e`). The last two calls draw centered text at y=8 and pass selection `-1` to `fn_3d2b0` (`0x33859`, `0x3387b`). | high |

## Data layout

| Address | Symbol | Layout and evidence |
|---|---|---|
| `0x55438` | `cur_bitmap` | 32-bit bitmap pointer. Stores at `0x337ec`, `0x33809`, and `0x33826` switch the draw destination; the panel remains current on return. |
| `0x5555c` | `crit_err_installed` | 16-bit flag, cleared by the word store at `0x337e3` after the installer call. |
| `0x55560` | `crit_err_message` | 32-bit text pointer loaded into EDX at `0x3384e`, immediately before the centered-text call. |
| `0x55564`, `0x55574`, `0x5557c` | `crit_err_panel_bitmap`, `crit_err_button_bitmap`, `crit_err_button_thin_bitmap` | Inline bitmap descriptors. Their opening little-endian word pairs are `(286, 48)`, `(58, 15)`, and `(58, 15)`, matching the draw arguments. The routine takes their addresses; it does not read their fields directly. |
| `0x55584` | `crit_err_control` | Inline control descriptor, passed by address in EDX at `0x33871`. This routine does not establish its full layout. |
| `0x62880` | `ui_color_base` | Palette byte. The AL additions at `0x33848` and `0x33863` wrap modulo 256 for the text (`base + 3`) and highlight (`base + 6`); `0x3386b` reloads the unadjusted base for the control. |

## T3 and T4

No T3 files are listed for this module. The Watcom 10.0a `-od` reference has a reported relative-call mismatch at the final call: original `0x3387b` targets `0x3d2b0`, while the reference comparison reports `0x33880`. The near-miss guard checks that the reference still fails byte matching.

The T4 test compares the original entry and compiled reference, observing the final bitmap pointer, the cleared flag, and the order and register arguments of all five calls. The installer stub sets the flag so that clearing it before, rather than after, installation would be observable. Palette cases cover ordinary values and both wrap thresholds. The stubs do not validate rendered pixels or the installer's real side effects. These checks have not been run here.
