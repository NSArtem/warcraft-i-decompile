# mod_13f60_c4 – two-player setup menu (reference functions)

Module `mod_13f60`, sources in `src/mod_13f60/`, header `src/include/mod_13f60.h`.
These six functions are the setup-menu state machine. Each handler sets the
byte `setup_state`, and `SetupMenuLoop` runs `dat_51718[setup_state]()` until
the state is 0x10.

| Addr | Function | Notes |
|------|----------|-------|
| 0x15668 | SelectGameTypeDialog | `DialogRun(0x17c,0,0x46,0x10,0)`; the result 0..4 picks `connection_type` and the next state (3/4, 0xa, 0xc, 0xd, 0). |
| 0x15ca8 | ModemConnectionDialog | Builds an 8-dword param block at 0x592c8 from `net_settings`, then runs dialog 0x182. Results: 0 = commit and state 0xe, 1 = state 2, 2 = state 0xb. |
| 0x15e1c | ModemSetupDialog | Dialog 0x183 with 4 dwords (pulse flag and three callbacks). On OK it copies the init/hangup strings, then calls `fn_1d538`. Always ends with state 0xa. |
| 0x16044 | DirectConnectionDialog | Dialog 0x184 with 6 dwords (baud index, port, irq index, `SetIrq`). State 2 on cancel, 0xe on OK. |
| 0x160f0 | NetGameStart | Calls `NetLinkStart`. On success it runs dialog 0x18d, then sets the state to 5 (play) or 0xf. For net play it calls `SetGameMode(3)` and sets state 0x10. |
| 0x162b0 | SetupMenuLoop | Loads art and sounds, starts music 0x10, runs the state loop, then frees everything. |

## Data
- `setup_state` and `setup_return_state` are bytes. `game_start_mode`,
  `connection_type`, `own_campaign` and similar are words.
- 0x592c8 is the modem dialog parameter block: dword 0 is the side, 1 the baud
  index, 2 and 7 the port, 3 the irq index.
- 0x51718 is the state handler table of 0x11 function pointers.

## T3 / T4 notes
- T3 files (`choose_campaign_dialog.c`, `connection_failed.c`,
  `network_connection_dialog.c`, `set_map_screen.c`) must still match.
- The six `*_reference.c` files are near-misses. Their remaining diffs are
  recorded in the blockers: a relocation for an unnamed data symbol or
  function, a jump displacement, or register allocation. The guard asserts
  they still do not match.
- T4 (`tests/test_mod_13f60_c4.py`) runs each reference against the original
  in the emulator. `DialogRun` is stubbed to return a chosen result, and
  callees are stubbed with their call logs compared. Callee addresses are
  looked up in the symbol DB. Globals are read at their DB addresses.
- `SetupMenuLoop` handler stubs write 0x10 to `setup_state`, so the loop
  exits after one iteration.
