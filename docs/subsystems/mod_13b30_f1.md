# mod_13b30_f1 — per-player unit/building counters (0x13b30..0x13dcb)

Unit fields used: type byte at +0x1b, owner byte at +0x1e, flags word at +0x10 (bit 0x80 = counted).

| Function | Addr | Notes |
|---|---|---|
| UnitCountAdd | 0x13c04 | Types 0x20..0x32 increment `player_building_count[owner]` (0x58e1e); others increment `player_active_men[owner]` (0x58e28). If flags&0x80: increments `unit_type_counter[type][owner]` when the pointer is non-null, then calls `unit_count_callback[type](u, +1)` (table 0x51408) when non-null. |
| UnitCountRemove | 0x13c84 | Mirror of Add using `dec` and delta -1 (edx = 0xffffffff). |
| PlayerStatsReset | 0x13d04 | Loop of 5 players (word stride 2, dword stride 4). Always clears the 0x58dxx/0x58exx per-player tables and `player_town_hall`. When the argument is 0, it also clears home point, training/dead counts, 0x50d98/0x50dac/0x50db6 and harvested gold/lumber. |

## Status
- The three functions are not yet byte-matched. The reference files differ from the original as follows:
  - Add and Remove: the `je` distance after the flags test is wrong (orig +0x7c vs ours +0x84).
  - PlayerStatsReset: register allocation only. The original keeps the argument in ecx and zero in esi.
- The T3-matched helpers are count_*_delta.c.

## Tests
`tests/test_mod_13b30_f1.py` covers three areas:
- T3 matching of the delta helpers.
- A near-miss guard that checks the references still do not match.
- T4 differential runs of the three references against the original code in the emulator. The unit tests sweep type, owner, flags, counter pointer and callback. The callback is stubbed at 0x13b30 and logs eax/edx. PlayerStatsReset watches the pre-filled tables.
